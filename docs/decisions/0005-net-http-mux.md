# 0005. net/http ServeMux over third-party routers

Date: 2026-09-13
Status: accepted

## Context

All four audited services use chi. Go 1.22 gave `net/http.ServeMux` method
matching, path wildcards (`/invoices/{id}`), `r.PathValue`, and precedence
rules, which covers what those services use chi for. gox is meant to be
generated by models as much as written by hand, and models know `net/http`
better than any router.

## Decision

- Handlers are plain `http.HandlerFunc`. Routes are registered with Go 1.22
  patterns on an `*http.ServeMux` (`a.HandleFunc("GET /invoices/{id}", h)`).
  No custom handler signature, context type or request wrapper.
- Middleware is `func(http.Handler) http.Handler`, composed by
  `middleware.Chain`. The default chain is fixed:
  route capture → recovery → request id → tracing → metrics → logging →
  timeout → max bytes → security headers → CORS (only with `WithCORS`) →
  auth (`WithAuth`) → `WithMiddleware` → mux.
- Route groups are expressed by wrapping: register protected handlers
  through a middleware, or split a subtree onto its own mux mounted with
  `Handle("/admin/", http.StripPrefix(...))`. A recipe documents both.
- Unmatched requests render the error envelope: `httpserver.Handler` asks
  the mux which built-in handler would run, then writes a 404
  (`not_found`) or 405 (`unimplemented`, with `Allow`) as JSON.
- The mux sets the matched pattern on the request it receives. Middleware
  such as `Timeout` and otelhttp hand the mux a derived request, so the
  pattern is resolved from the mux by `RouteCapture` at the top of the chain
  and stored in the context before any request copy is made. Logging,
  metrics and span names read the pattern from there.
- Timeout is real cancellation: the response is buffered and the handler's
  context is canceled at the deadline; the client gets a 504 envelope.
  Streaming handlers must not sit under it.

## Dependencies added

The root module now depends on the OpenTelemetry SDK, its OTLP exporters,
the Prometheus exporter and `otelhttp`, as the plan allows. Two extra
dependencies come with that and are justified here:

- `github.com/prometheus/client_golang`: `pkg/otel` needs `promhttp` to
  serve the registry the OpenTelemetry Prometheus exporter writes to, and
  the Go and process collectors so `/metrics` includes runtime metrics.
- `github.com/felixge/httpsnoop` and friends arrive transitively through
  `otelhttp`.

They are imported only from `pkg/otel` and `pkg/middleware`, never from
the root package directly, which depguard enforces.

## The old modules

The former `github.com/guilhermebr/gox/http` and `.../logger` modules are
not re-implemented over the new packages: doing so would have made those
tiny modules depend on the root module and drag the OpenTelemetry SDK into
every consumer that only wanted a logger. They were removed; consumers
pinned to their pseudo-versions keep resolving them.

## Consequences

- chi's `URLParam` becomes `r.PathValue`; `r.Route`/`r.Group` become
  middleware wrapping or a mounted sub-mux.
- oapi-codegen users switch the server target from `chi-server` to
  `std-http-server`.
- No regex routes, no route-level middleware syntax. Both are available
  through wrapping and are documented as recipes rather than API.
