# Decisions

Why gox is built the way it is, one ADR per choice. Read this index, then
only the ADR you need. An ADR records a decision as it was taken; Notes
flags where the code has moved on since, and the code wins. An ADR whose row
has a note says so in an `Amended:` line under its Status. To change a
decision, write a new ADR and note it in the old one's row (format and
numbering: `docs/AGENTS.md`).

| ADR | Decision | Notes |
|---|---|---|
| [0000 Module layout](0000-module-layout.md) | A root module (the root package and `pkg/*`) plus one module per feature, provider and utility, tagged per module (`vX.Y.Z`, `<module>/vX.Y.Z`); `go.work` joins them locally. | Its module list omits `jobs` and `openapi` and names `supabase` as the only provider: `go.work` is current. There is no CI matrix (CI runs `make ci` and `make test-integration`) and no `make release`. A module not yet released may still require gox `v0.0.0` with a local `replace`. The root module also requires `prometheus/client_golang` (`pkg/otel`, 0005). Adding a module follows `.claude/skills/gox-add-module/SKILL.md`, not the list under Consequences. |
| [0001 One root import](0001-root-vs-feature-split.md) | A plain service imports only the root; a heavy integration is a package the service opts into by importing it and passing its `Enable()`, with a `From(app)` accessor. No build tags, `init()` or blank imports. | The root package also links `prometheus/client_golang` through `pkg/otel` (0005). Not every feature has `From`: `openapi` has no config or accessor (0010), and `web` hands out per-request values (`PageFrom`, `SessionFrom`, `APIFrom`). |
| [0002 No DI framework](0002-no-di-framework.md) | No fx, dig or wire: options declare what a service needs, components start by stage and stop in reverse, feature values come from typed accessors. | Its `b.Component` example is for feature packages: services never touch `Builder` and use `gox.Component(c)` or `a.Add(c)`. |
| [0003 Config](0003-config-strategy.md) | `gox.New` loads `gox.BaseConfig`, the service's struct and every feature section in one `ardanlabs/conf/v3` pass under one prefix; `--help` lists every variable; secrets carry `mask`; the environment is the only source. | Command-line flags set the same fields: `conf` reads `os.Args`, and `--help` lists them under OPTIONS. 0015 added `gox.WithEnvAlias` for unprefixed platform variables (`DATABASE_URL`); `PORT` stays the only alias built in. |
| [0004 Error model](0004-error-model.md) | Coded errors with a public-safe message, public details and a private cause, rendered as one flat JSON envelope; `gox.WithErrorMapper` translates a service's own sentinels. | 0007 renders framework rejections as HTML error pages for HTML requests (`Builder.ErrorRenderer`); 0009 made the envelope replaceable (`gox.WithErrorRenderer`, `gox.ProblemJSON`). |
| [0005 net/http ServeMux](0005-net-http-mux.md) | Plain `http.HandlerFunc` on Go 1.22 `ServeMux` patterns, `func(http.Handler) http.Handler` middleware in a fixed chain, unmatched routes as the envelope, a timeout that cancels. No third-party router. | The chain it lists lacks error renderers, client IP, error mappers, cross-origin protection and feature middleware: `HTTP()` in `http.go` has the current order. Every public route sits under the timeout, with no per-route opt-out, so `HTTP()` serves no streaming responses (SSE, WebSockets, flushed chunks). No recipe shows a mounted sub-mux or regex routes. oapi-codegen generates types only; `std-http-server` is not used (0010). |
| [0006 Migrations](0006-migrations-tool.md) | golang-migrate over embedded SQL, run at boot after the ping on one dedicated connection, never the pool; `POSTGRES_MIGRATE=false` leaves it to a deploy step calling `postgres.Migrate`. | The scaffold, guide and recipes embed from a `migrations` package (`migrations.FS`); the runner accepts either form. |
| [0007 gox/web](0007-web-templ.md) | Server-rendered HTML on templ, Alpine.js, HTMX and plain CSS: one layout, `web.Page`, sealed cookie sessions with CSRF, flash, `web.Form` and HTML error pages. | The API listing lacks `WithCSRFExempt` and `Session.IsAuthenticated`: `go doc github.com/guilhermebr/gox/web` is current. CSRF skips exempt prefixes and requests sent with a non-form `Content-Type` (JSON). `web.Error` and `gox.Error` are the same call (`httpx.Error` with the request's renderers), so `gox.Error` also renders the error page for HTML requests; the docs use `gox.Error`. |
| [0008 Providers and WorkOS sessions](0008-providers-and-workos-sessions.md) | Third-party clients live in `providers/<name>`, one module each: wrap the vendor's official SDK, return it from `From`, add only config, lifecycle and HTTP edges. WorkOS leaves token checks to its SDK and owns the cookies. | `providers/s3` returns `storage.Bucket` from `From`, not the SDK client (0013). Two depguard rules cover the directory: `providers` (no feature, test files included) and `provider-siblings` (no other provider, in non-test files only; it also keeps each provider one package). Since `providers/workos/v0.1.1` the provider picks the trusted issuer (`WORKOS_ISSUER`, default `<API base URL>/user_management/<CLIENT_ID>`) and passes it to the SDK. Since v0.1.2, when the SDK refuses a token for want of a signing key (a WorkOS key outage), the provider fetches the key set itself and repeats the SDK's checks (`keys.go`) to decide whether to keep the cookie; the request stays anonymous, so authentication is still the SDK's. |
| [0009 SPA, error shape, cross-origin](0009-spa-errors-and-cross-origin.md) | `gox.WithSPA` serves a single-page app from the API's origin; `gox.WithErrorRenderer` replaces the envelope (`gox.ProblemJSON` for RFC 9457); net/http cross-origin protection is on by default. | |
| [0010 OpenAPI validation](0010-openapi-request-validation.md) | `openapi.Enable(documents...)` validates requests against OpenAPI 3.x as feature middleware; undescribed requests pass; a violation is `invalid_argument`. No code generation; responses are checked in tests. | `gox.WithAuth` runs after every feature middleware, so after validation whatever the option order; only feature auth such as `jwt.Enable(jwt.WithAuth())`, passed before `openapi.Enable`, runs first. Generation is types only (`oapi-codegen -generate types`, `docs/recipes/start-from-a-contract.md`) and routes are always registered with `a.HandleFunc`: `std-http-server`'s `HandlerFromMux` would be a second way to register a route, and a generator that emits its own router (ogen) buys compile-time routing at the cost of a second router, error model and middleware API in one binary. Types keep the contract on the payloads, where drift happens. |
| [0011 Jobs on River](0011-jobs-on-river.md) | `gox/jobs` wraps River on the service's Postgres: transactional enqueue, retries, schedules that fire once per fleet; `jobs.Enable(postgres.From)` because features never import each other. | |
| [0012 Temporal provider](0012-temporal-provider.md) | `providers/temporal` returns the SDK client, checks the server at boot and in `/readyz`, and runs one worker per task queue that starts and drains with the app; `TEMPORAL_WORK=false` only starts workflows. | |
| [0013 Object storage](0013-object-storage.md) | `pkg/storage` holds the stdlib-only `Bucket` interface and signed upload tokens; each backend is a provider (`providers/s3`); clients upload through presigned URLs and never name a key. | Services also import `pkg/mail` (0014), `pkg/i18n` (0015), `pkg/middleware` and `pkg/httpclient` directly. Google Cloud Storage is `providers/s3` with `S3_COMPAT`, not a separate provider. |
| [0014 Mail](0014-mail.md) | `pkg/mail` holds `Message`, the `Sender` interface, SMTP, the `Restrict` staging guard and `Recorder`; each vendor is a provider (`providers/mailgun`). No templates, no queue. | |
| [0015 Request helpers](0015-request-helpers.md) | Small helpers with no new dependency: trusted-proxy client IP, per-route rate limit, keyset pagination, `gox.WithEnvAlias`, `postgres.TxWith` and `pkg/i18n`. | `postgres.TxWith` lives in the postgres module, not the root. |
